# 答题对战

双方初始 100 HP，每题低分方扣除双方总分差值，最低为 0；归零后点击继续进入结算，题目用尽时按剩余血量判胜负。题目难度决定本题作答窗口：easy 25 秒 / medium 30 秒 / hard 45 秒，速度加分阈值按比例缩放（25s：4/8/12/17/25，30s：5/10/15/20/30，45s：8/15/23/30/45）。对手难度同时决定抽题权重（入门 70/25/5、普通 40/45/15、困难 15/45/40、地狱 5/25/70，顺序为 easy/medium/hard），题库缺某难度时剩余权重自动重新分配。配置 API Key 后，揭晓答案时额外请求一次教育复盘，包含选项比较、可能误区与学习建议；失败时保留题库解析。该请求沿用 320 tokens 上限。复盘不展示模型内部思维链，错误原因作为可能解释呈现。

侧边栏向访客、学生和管理员开放。对战设置页按「题库（公共/我的）→ 科目 → 主题 → 题量（3/5/10/∞）」顺序组织，四项使用等宽 grid 排在同一行；「更多设置」中的对手等级、初始血量、AI 也并排一行，主题随科目联动。按钮放在设置卡片内部的底部操作条（「开始对战」+「成就」），不再挂在滚动容器外层被卡片挤出可视区域。题量选 ∞ 时反复出题直到一方血量归零（题用完自动重新洗牌），有限题量用尽则按剩余血量判胜负。四档对手选择（普通/困难/地狱等）保留在「更多设置」。

每题双方同时开始，限时 30 秒。正确分为 100；正确作答且用时不超过 5、10、15、20、30 秒时，时间分分别为 50、40、30、20、10。错误或超时没有正确分与时间分。额外分单独保留，默认 0。总分相同为平局。

设置中选择 Local 使用本地模拟，选择 API 则复用现有 AI 设置与客户端。`LocalOpponent.answer(question, level)` 和 `ApiOpponent.answer(question, level)` 共用返回契约 `(选项文本, 思考秒数)`，可替换为其他提供者。

API 在后台线程请求，只发送题干和文字选项，附带等级控制词，校验返回的选项索引和时间范围；网络实际耗时也计入作答时间，30 秒未返回按未作答处理。API 的准确率为提示词目标，不能保证严格达到统计概率。Local 模式则由程序控制：入门级准确率 50%，延迟 12–24 秒；普通级 72%，8–18 秒；困难 88%，4–12 秒；地狱 97%，2–7 秒。概率是长期目标，不保证单轮比例。错误时更偏向选择与答案文字相似的干扰项。双方锁定后统一揭晓结果。

对手角色设定：你是参与学习对战的真人风格玩家，依照所选等级表现出思考、犹豫与失误；不要提前揭示答案。未来接入语言模型时仍由本地规则限制等待时间与概率。

头像使用根目录 AI-assistant-icon.png。当前以文字显示思考/锁定状态，尚未生成额外表情素材。对战结果独立于普通练习成绩、每日目标与错题本，当前仅在本轮会话内展示。
# 决策与讲解分离 · 2026-11-13

API 模式将当前题目 ID、题干和选项发送给模型，不发送标准答案、题库解析或图片。模型一次返回结构化决策：题目 ID、选项索引、模拟耗时及简短选择依据。程序校验题目绑定、索引范围、有限耗时和依据包含所选项，保存不可变 OpponentDecision，结算后展示同一份依据及独立的题库解析。结算不再额外调用生成式讲解接口，也不把随机选择描述成模型解题。显示内容是模型提交的决策摘要，不代表内部推理轨迹；结构校验不能保证语义正确。

Local 保留原等级概率模拟，并明确标识其不是真实模型解题。已配置密钥时默认选择 API。API 等级控制检查要求及模拟等待范围，不再要求模型按正确率随机答错；因此实际正确率不保证达到固定比例。等待秒数属于游戏模拟参数，不是 API 推理实测耗时。接口失败按未作答处理，不偷偷回退随机答案。

# 三阶段动态展示

2026-11-13：作答时使用“读题 → 分析选项 → 选择并检查”的替换式活动提示，上一段不累积。该进度是按等级等待时长播放的界面表现，不代表模型内部处理进度。选项判断与答案继续保密，双方结束后展示 API 随同选择提交的三段简短教育摘要及题库解析，不再保留提交状态文案。API 未返回摘要时使用已保存的简短选择依据，不伪造分析。

# 对战图片输入 · 2026-11-13

API 对战现在将题干图片及选项图片作为带标记的 Base64 内容块发送，保留题目 ID、题干及选项；不发送答案键或题库解析。仅接收项目目录内实际存在的图片，按文件内容识别 PNG/JPEG/GIF/WebP，单图上限 8 MiB、总计 16 MiB。无法读取或格式不支持时本题不作答，不静默丢弃图片后猜答案。

官方 DeepSeek 地址的图片请求使用 `deepseek-flash`，纯文本请求仍使用设置中的模型，不更改保存的设置。自定义兼容接口沿用配置模型，使用者需选择支持图像输入的模型。Local 仍是概率模拟，不具备视觉理解。玩家侧同步展示选项图。

协议参考：https://api-docs.deepseek.com/guides/vision/ 。自动测试使用模拟网络响应，尚未以真实密钥验证识图质量。

# 接口异常处理

提交前修复：接收响应时首先检查 30 秒截止时间，迟到响应不会进入选择及扣血分支。2026-11-13 已使用本机配置进行一次真实视觉接口联调，MAT009 返回选项 5 与三段摘要；该结果仅覆盖单题联通与解析，不代表所有图题均能正确识别。

2026-11-13：接口错误、结构校验失败或未得到决策的请求超时均使当前轮次作废；不累计成绩、不计算血量差，不展示伪造答案。保留双方血量和前轮记录，显示错误原因，提供“重试本题”。结构化作答采用独立系统约束和 JSON 输出模式，输出上限为 800 token；普通伴学维持 320 token。输出被截断时报告错误，不尝试从残缺 JSON 猜测选项。真实服务错误需根据页面显示的原因排查，模拟网络测试不等同于真实接口验证。

# 海克斯强化卡 · 2026-11-20

设置页点「开始对战」后先进入三选一强化页，再开打。按卡牌现有权重从全池不放回抽取三张不同强化，稀有度不固定，可出现同稀有度多张卡；高稀有度不保底。选定后整局生效，重开重置；不选卡时 `AugmentRuntime(None, hp)` 保持原有规则，旧调用完全兼容。

- 白银：锋锐思维（答对 +30 分）、厚壳（首次答错免伤）。
- 黄金：时间沙漏（每回合 +8 秒）、知识掠夺（我答对且对手答错额外扣 15 血）、连胜狂热（连对加分，答错重置）。
- 棱彩：洞察之眼（每回合排除一个错误选项）、绝境反冲（残血 ≤30% 答对得分翻倍）、双刃剑（得分翻倍但答错自伤 15）。
- 魔王：魔王契约（玩家答题时间减半，本题总得分 ×3；原造成 3 倍伤害效果已移除）。

发牌页用纯 Canvas 绘制卡片，四张错峰上浮并渐显，棱彩 / 魔王边框持续流光；每轮对战页与结算页用同款稀有度横幅（AugmentBadge）展示当前强化。卡牌动画只作用于卡片本身和横幅，不改动背景、导航栏或窗口透明度，不露出桌面。英文模式文案写在 `locales/en.json`。规则实现在 `augments.py`，绘制在 `augment_ui.py`，效果运行时 `AugmentRuntime` 统一承接，UI 不按卡牌 id 硬分支。`grade()` 新增可选 `limit` 参数，加时卡不污染全局 `ROUND_SECONDS`。

# 掉血演出与自动进题 · 2026-11-20

血量从 ♥ 数字改为 Canvas 血条（`battle_fx.py` 的 `HealthBar`），用 Motion.tween 平滑补间填充宽度与数值；血量比例 ≤30% 变红、≤60% 变黄，掉血时短暂闪色。双方血条**左右并排在同一行**（`battle_ui.round()` 用两列等宽 grid，`row=0`、`column=0/1`），每条内部为「名字 + ♥ + 血条 + 数值」。两条血条共用按实际字体测量的统一名字列宽（`label_width`），红心、血条起点、血条终点和数值文本严格落在同一组 x 坐标，等宽列保证两者几何完全相同；轨道带细描边，0 血时仍能看清整条轨道。结算按伤害方向切换大肥鱼立绘：对手掉血显示被砸（attacked）并闪对手血条，对手归零显示倒地（die）；玩家掉血显示大肥鱼喷水（attack）并闪玩家血条。三张动作图由根目录 JPG 抠白底生成透明 PNG，放在 `assets/battle/ai_assistant_{attacked,die,attack}.png`，内部白色（围裙、光环）保留。

**可换肤立绘系统**：对战立绘统一由皮肤包提供，放在 `assets/battle/skins/<skin>/<state>.png`，共 7 个状态（normal 一般 / thinking 思考 / correct 答对 / wrong 答错 / attack 喷水 / attacked 被砸 / die 倒地），全部为独立透明 PNG。`skin_registry.json` 声明皮肤清单、显示名和每态文件；`learning_platform/skins.py` 的 `skin_for_difficulty()` 按难度选皮肤（「地狱」→ `hell`，其余 → `default`），`portrait_path()` 按「请求皮肤 → default → 旧扁平文件」逐级回退，绝不空图。`BattlePage._portrait_source()` 走这套解析，`_skin_id` / `_hell_art` 供测试断言。

- **default 皮肤**：由旧资源迁移——thinking/correct/wrong 从 `expressions.png` 三帧拆出（normal 复用 thinking），attack/attacked/die 来自 `ai_assistant_*.png`。
- **hell 皮肤**：黑红哥特风，共 7 张——thinking/die/attack/attacked 由原四张 JPG 泛洪去背生成（attack 原黑底），新建的 normal（愤怒待机脸，原黑底）、correct（绿勾，白底合图左半）、wrong（红叉，白底合图右半）由用户新增的两张 JPG 泛洪去背生成，保护了气泡白底 / 白发 / 星星 / 白色描边。旧 `assets/battle/hell/` 目录已删除，内容全部进入皮肤包。

新增皮肤只需在 `skins/` 下建同结构文件夹并加一条注册表配置，无需改代码——为将来开放换肤功能预留。详见 `docs/ASSET_IMAGES.md`。

结算后不再手动点继续：延迟 3 秒自动进入下一题，中途（900ms）显示「正在进入下一题……」提示；最后一题或任一方归零则显示「正在查看对战结果……」后自动进入结算页。所有延迟用 `after()` 并按 `generation` 校验，切页 / 退出时 `_cancel_pending()` 取消，避免过期回调重建页面。API 作废、超时等异常仍走原来的「重试本题」分支，不计分不扣血、不自动前进。

# 题目卡对齐血条 + 中间文字真正居中 · 2026-11-20

按用户红线标注图修复两处：

- **左右对齐**（两次修正后才真正生效）：血条 header 与底部 dock 直接挂在 `outer`、左右内边距 `SPACE_4`（16）。第一轮发现滚动题面被双重缩进，把 canvas window 与 body frame 都设成 `SPACE_4`；但用户截图仍显示右边缘内缩约 30px。**根因有两个**：① 垂直滚动条出现时只让 `canvas` 变窄约 10px，`outer` 和 header 不变，按 `event.width`（canvas）算 `content_w` 就少了一截；② body frame 自己的 `SPACE_4` padding 与 canvas window 的 `SPACE_4` 叠加，又各吃掉 16px。最终方案：`Application` 新增 `_body_match_outer`，battle `round()` 调用 `set_body_side_pad(SPACE_4, match_outer=True)` 让 `_on_canvas_configure` 改用 `outer.winfo_width()` 计算，并把 `body` 的横向 padding 归零（`padding=(0, SPACE_1)`）；`clear()` 复位 `match_outer=False` 与 `PAGE_PAD`。实测真实窗口下血条与题目卡同为 x=274→1058（无滚动条）、x=378→1222（有滚动条），完全重合。注意 `winfo_rootx()` 对 canvas 内嵌控件有固定 −16px 报告偏差，验证几何必须用 `canvas.bbox(window)` + `canvas.winfo_rootx()`，不能直接比较 root 坐标。
- **居中生效**：上一版给 `AssistantReply` 配了 `justify="center"`，但 tk.Text 没有 widget 级 `-justify`，且**内建 `all` tag 在本平台不响应 `justify`**（受控测试 bbox 仍在 x=2）。改为具名 tag `aligned` 并在每次 `configure(text=...)` 后 `tag_add("aligned","1.0","end")`。注意范围必须到 `end`：Tk 用行尾换行符上的 tag 决定该行对齐，停在 `end-1c` 会让最后一行仍是左对齐。短行（「正确答案」）实测已居中（bbox x≈105 / 宽 332）。

回归测试 `test_battle_cards_share_health_bar_inset_and_result_is_centred` 断言唯一 inset 为 `SPACE_4`、`match_outer=True`、body 横向 padding 为 0、canvas 窗口 bbox 与 header 内宽一致，并验证居中走具名 tag 且覆盖到 `end`。全套 179 项通过。

### 血条与卡片中间分界对齐（青线标注图）

用户用青色虚线标出「血条行与卡片行应共用同一组左边缘/右边缘/中间分界」，指出中间错位约 48px、右侧错位约 18px。**根因**：血条和卡片是两套独立的 grid padx 写法——血条 `padx=(0,SPACE_2)` + `(SPACE_2,0)`（中间缝 16px、左右对称）；而卡片原本是 `(0,SPACE_3)` + `(0,0)`（中间缝 12px 且右列不留白），导致右卡比左卡宽 12px、中间缝中心偏移。`battle_ui.round()` 改为让两张卡复用血条的**对称列结构**：`player_card.grid(padx=(0,SPACE_2))`、`ai_card.grid(padx=(SPACE_2,0))`，两列 `uniform="battle"` 等权。实测换算（canvas bbox 消除 `winfo_rootx()` 的 −16px 报告偏差）后：血条与卡片同为 x=288→1072、中间缝中心同为 x=680，完全重合。回归测试新增断言：两卡与两血条各自等宽、左右卡 padx 对称（`lp[0]==0`、`rp[1]==0`、`lp[1]==rp[0]`）。全套 179 项通过。

# 魔王飘字崩溃与特效丢失修复 · 2026-11-20

修复「选魔王海克斯后一堆 bug」：`battle_fx.py` 引用的是原始 `tokens` 门面（颜色只作为 `palette()` 字典键存在，没有模块级 `T.BG`），但飘字帧写了 `T.mix(T.BG, ...)`。动效开启时 Motion 的 `tween()` 会同步执行 `frame(0)`，随即抛出 `AttributeError: module 'learning_platform.tokens' has no attribute 'BG'`，异常沿 `_stage_damage()` 冒泡中断 `finish_round()`——结算文本不刷新、自动进题定时器不排，表现为整局卡死。取色改为 `T.palette()["BG"]`，与同文件其余取色一致（项目另有 `ui_tokens` 门面才用 `T.BG`，两套门面需分清）。

# 魔王回合对手计分修正 · 2026-11-20

修复魔王卡下「大肥鱼答对却显示红色、计分为 0」的问题。根因是玩家的 7 秒限时被同时传给对手决策判定：普通级对手常在 8–18 秒才锁定答案，`grade()` 发现耗时超过 7 秒就把正确答案记成 0 分，结算颜色随之变红；若接口响应更晚还会直接触发「等待对手决策超时」而整轮作废。

现在 `round()` 分离两套时间：`player_limit`（海克斯决定玩家倒计时）和对手侧两种窗口——`ai_limit` 是沿用原有 30 秒的响应截止，只用来拒绝迟到决策；`ai_grade_limit` 同样是 `ROUND_SECONDS`，用于对手计分。`receive_decision()` 不再拿玩家的 7 秒判对手迟到；`_score_opponent()` 按正常 30 秒窗口给对手分。玩家超时仍严格按 7 秒结算，三倍伤害照常生效；对手正确答案保持绿色、正常扣血。回归验证覆盖 12 秒才锁定的正确答案、玩家血量不反扣、结算颜色与「魔王契约」提示文案。
